# 输出文档模板（固定结构）

本文件定义 `skills-description.md` 与 `skills-health.md` 的**固定章节结构**。
每次生成的文档形态一致，因此两次整理之间可以做行级 diff，只看变化行即可。

---

## A. `skills-description.md`

路径：`~/.agents/skills/skills-description.md`（**每次直接覆盖旧文件，不备份**）

### 头部元信息

```markdown
# Skills 能力说明书

> 扫描路径：`~/.agents/skills/`　·　扫描日期：YYYY-MM-DD　·　现存 Skill 数：**N**
> 说明：本文档记录每个 Skill 的**功能**、**内容（核心机制）**、**适用领域**、**关联关系**与**调用方式**。
```

### 章节一：总览

按能力分类的速查表。分类由模型归纳，**同一批 skill 的分类应保持稳定**（便于 diff）。

| 分类 | Skill | 一句话职责 |
|---|---|---|
| **<分类名>** | `skill-name` | <一句话> |

### 章节二：主表

**每个顶层 skill 恰好一行**，6 列固定，顺序固定：

| Skill | 功能（做什么） | 内容（核心机制） | 适用领域 | 关联（调用 / 被调用 / 依赖） | 触发方式 | 产物 |
|---|---|---|---|---|---|---|

各列的填写要求：

- **功能**：一句话，回答"它替用户做了什么"。
- **内容**：**提炼 SKILL.md 正文里的机制**，不是复述 description。写清楚它分几个阶段/步骤、每步的关键约束是什么。若正文只声明了原则而没有步骤，就写它规定了什么原则。
- **适用领域**：它解决的是哪一类问题、适合什么规模的场景；不适用什么。
- **关联**：它调用谁、被谁调用、依赖谁；涉及文件依赖（如指向某 skill 的 `references/`）时一并写出。
- **触发方式**：`模型可自动触发` 或 `需手动调用（disable-model-invocation）`。
- **产物**：它写出的文件/代码/对话结果。没有则写"无（纯对话）"。

### 章节二之二：示例 / 子技能

**仅当存在嵌套 skill 时才出现此章节**（扫描 JSON 中 `depth > 0` 的项）。
不混入主表，因为它们通常是某个生成器的产物，而非独立能力。

| Skill | 所属父 skill | 功能 | 触发方式 |
|---|---|---|---|

### 章节三：关系图

ASCII 图，按**线路**分组（决策主线 / 架构维护 / 诊断修复线 / 领域语言线 / 知识管理线 / 元工具线等）。
箭头方向表示"调用 / 产出流向"；断链处用 `（缺失）` 标注。

### 章节四：依赖矩阵

| Skill | 依赖（内部） | 被依赖 | 缺失依赖（已删除导致的风险） |
|---|---|---|---|

第三列是**体检结论的主要落点**：凡是引用了目录中不存在的 skill 的，在这里点名。

### 章节五：组合工作流

| 场景 | 组合 |
|---|---|
| **<场景名>** | `skill-a`（做什么）→ `skill-b`（做什么）→ … |

### 章节六：注意事项

体检结论的落点。每条一行：**现象 → 影响 → 交给人执行的动作**。

无法由脚本判定的语义问题（功能重叠、疑似指令冲突、孤儿 skill）也写在这里，
但必须标明**这是待人工判断的线索，不是结论**。

**这一章描述的是"需要人来决定什么"，不是"接下来做什么"。**
措辞上避免写成祈使句式的待办（"改成 X"、"删除 Y"），
而写成"**若要修，改成 X**"、"**该留哪个由你决定**"。

## B. `skills-health.md`

路径：`~/.agents/skills/skills-health.md`（**每次直接覆盖旧文件**）

它是**行动项清单**，但**不是执行计划**——它写给人看，**skill 本身不执行其中任何一条**。

```markdown
# Skills 体检清单

> 生成时间：YYYY-MM-DD　·　对应说明文档：`skills-description.md`
> 说明：本文件只列**待处理项**。说明性内容请看 `skills-description.md`，不要在此重复。
> **本清单中的命令由人执行，本工具不会执行它们。**

## 必处理

| ☐ | 类型 | 涉及 skill | 现象 | 交给人执行的动作 |
|---|---|---|---|---|
| ☐ | 失效引用 | `decision-mapping` | 正文调用 `/X`，该 skill 不存在 | 改写为可执行动作，或补建该 skill；给出确切命令 |
| ☐ | 失效引用 / 命名不一致 | `decision-mapping` | 正文调用 `/grilling`，实际 skill 名为 `grill-me` | 把 `/grilling` 改为 `grill-me`（3 处）；给出 `sed` 命令 |
| ☐ | 引用写法不统一 | `some-skill` | 已知 skill 被写成 `/xxx` 形式 | 统一为反引号名式 `` `xxx` `` |
| ☐ | 共享产物不一致 | `ubiquitous-language` | 写 X.md，另一 skill 读写 Y.md | 统一到同一文件，并给出迁移说明 |
| ☐ | 硬编码路径 | `obsidian-vault` | 写死 `/mnt/d/Obsidian Vault/...` | 改为运行时从 `$OBSIDIAN_VAULT` 读取 |

## 建议处理

| ☐ | 类型 | 涉及 skill | 现象 | 交给人执行的动作 |
|---|---|---|---|---|

## 仅记录（需人工判断，勿直接照做）

| 类型 | 涉及 skill | 现象 |
|---|---|---|
| 疑似功能重叠 | `a` / `b` | … |
| 疑似指令冲突 | `c` | … |
| 孤儿 skill | `d` | 无其他 skill 引用它（可能是独立工具，非问题） |

## 已处理

| ☑ | 类型 | 涉及 skill | 处理方式 | 处理日期 |
|---|---|---|---|---|
```

**关键措辞**：
- 列名用 **"交给人执行的动作"** 而不是 "建议动作" / "下一步" / "TODO"——
  后者读起来像待办清单，会诱导执行者（包括本 skill 的下一次运行）直接动手。
- **"已处理"区默认留空**。只有**人**真的处理完了，才把条目移过去。
  本 skill 不得自行往"已处理"区写内容。
- **"仅记录"区不预填勾选框**，因为这类条目未必需要处理。
